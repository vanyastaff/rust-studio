# T07 — Гейт на frontmatter агентов

**Требования:** G02, G03, R06i · **Зона:** `plugins/rust-studio/scripts/validate-distribution.sh`
· **Блокеры:** T02, T03 (тот же файл) · **Волна:** после них

## Что не так (измерено контрольным тестом)
`claude plugin validate --strict` **не смотрит frontmatter агентов вообще**. Проверено
подсадкой в `agents/rust-scout.md`:

| Подсаженный ключ | Вердикт валидатора |
|---|---|
| `totallyMadeUpKey: banana` | **принято** |
| `permissionMode: not_a_real_mode` | **принято** |
| `isolation: teleport` | **принято** |

Значит опечатка в `disallowedTools`, кривое значение `model:` или выдуманный ключ в любом из
33 брифов уезжают к пользователю молча. Скиллы такой гейт имеют (`unknown skill frontmatter
keys`), агенты — нет.

## Приёмка
1. Гейт в `validate-distribution.sh` проверяет frontmatter каждого `agents/*.md`:
   ключ вне известного набора → падение с именем файла и ключа. Известный набор снять с
   действующих файлов (`name`, `description`, `model`, `disallowedTools`, `color`, `memory`)
   и расширять осознанно, как это сделано для скиллов.
2. Значение `model:` проверяется против набора, который плагин реально использует
   (`inherit`, `sonnet`, `opus`, `haiku`) — не против выдуманного списка.
3. `name` совпадает с именем файла — как у скиллов.
4. Гейт доказан намеренной регрессией по каждому классу.
5. Четыре гейта зелёные.

## Не делать
Не добавлять в брифы `permissionMode`, `isolation`, `maxTurns` и прочее из аудита: проверить,
honor-ит ли их хост, отсюда **нечем** — валидатор принимает что угодно. Непроверенное поле в
33 файлах хуже отсутствующего.
