# Close a session with a usable handoff

Inspect this branch's actual diff/log and relevant retained task artifacts. Summarize changed,
done, in-progress and blocked work, giving each open item its next action. Separate local
completion, destination-tree integration and remote merge. Record which checks actually ran
and what remains unverified.

## Preserve continuation

For an active design in docs/designs, its legacy location or an explicit project location,
update only authorized task statuses and execution entries under
`references/task-continuity.md`. Preserve destination-tree evidence, repair counts,
dependencies and unresolved blockers. Stale worker evidence cannot become a completed row.
Link the original request, accepted amendments and authoritative context so the next worker
can reconstruct the task without private conversation history.

Identify non-obvious durable learnings. Persist them through
`references/procedures/writing-memory.md` only with user/host authorization; otherwise list
proposals. Surface index-budget/integrity warnings for review-work memory. A repeated
correction calls for a promotion proposal: deterministic lint/CI check when decidable,
project rule when it binds everyone, or convention note otherwise. Name the owner and exact
proposed line under `references/memory-protocol.md`.

## Review observed friction

When concrete friction occurred, use this session's searches, commands, corrections and
available redacted logs to propose zero to three improvements. Inspect other sessions only
within the requested scope. Each proposal connects observed event, cause or labeled
hypothesis, smallest change and validation. Consider navigation, repeated/oversized output,
missing diagnostics and mistakes a deterministic check or scoped rule could catch.

Reuse an existing index/rule owner before adding instructions. Missing diagnostics may justify
local stderr capture; they grant no new production access, secrets or global configuration
changes. Keep effective safety and acceptance checks. One unused step does not prove it is
unnecessary, and savings require before/after evidence. Separate proposals from completed
work. With no observed friction, omit the retrospective.

## Deliver

Return a short recap, evidence, captured/proposed learning paths and one concrete next action.
Coherent uncommitted work can suggest publish-change commit/PR, completed task plans can
suggest verify-work acceptance, user-facing changes can suggest write-docs changelog, and
remaining defects/design gaps can name their available workflow. Suggestions do not invoke
explicit-only actions. Existing authorization may continue; a handoff-only request ends here.
No cleanup, force-push or hook bypass is part of closing a session.

Completion requires enough state for another worker to identify current artifacts, remaining
work and the next check. Write a handoff file only where requested or already authorized;
otherwise deliver it in chat. End **COMPLETE / NEEDS WORK / BLOCKED** for the handoff scope,
without upgrading the underlying implementation's status.
